# تحليل رحلتي العميل والفني وتطوير صلح 1.9

## بنية التطبيق

المستودع تطبيق Flutter واحد بواجهتين بحسب الدور، وليس مشروعَي Android منفصلين. المسار الحقيقي يستعمل Supabase Auth وواجهة upyogi-api، بينما النسخة التجريبية الجديدة تعمل محليًا دون بيانات دخول. الجلسة الحقيقية لها الأولوية عند بدء التطبيق. اختيار «استخدام حساب حقيقي» يبقى متاحًا في الرحلتين.

## العميل

| المرحلة | السلوك المطور | حالات يجب مراعاتها |
|---|---|---|
| الترحيب | تعريف بالتجربة وتسجيل اسم افتراضي دون كلمة مرور | العربية والإنجليزية، عرض صغير، استئناف لاحق |
| الاستكشاف | 24 خدمة في 8 تصنيفات وثلاث مدن | رسالة عند غياب النتائج ومسح الفلاتر |
| البحث | نص عربي/إنجليزي، مدينة، تصنيف، ترتيب بالسعر أو التقييم، سقف سعر | إزالة التشكيل وتوحيد أشكال الألف والياء |
| المفضلة | إضافة وإزالة وحفظ الخدمات | الخدمة المعطلة تختفي من نتائج العميل |
| التفاصيل | وصف الزيارة والمدينة والسعر التجريبي | السعر وتفاصيل الخدمة تُنسخ للحجز ولا تتغير لاحقًا |
| الموعد | يوم ووقت وعنوان وجوال وملاحظات، وتعبئة افتراضية | موعد مستقبلي، رقم صحيح، منع التداخل |
| الطلب | رقم مرجعي وحالة وسجل مراحل | منع تكرار الإنشاء والانتقالات القديمة |
| التعديل | إعادة جدولة الطلب الجديد وإلغاء الجديد أو المقبول | لا إلغاء أثناء التنفيذ أو بعد الانتهاء |
| المتابعة | رؤية قبول الفني والتحرك والعمل والإكمال | التقدم الافتراضي مرتبط بالطلب، وليس GPS حقيقيًا |
| الدفع | ملخص القيمة ثم تخطي أو تسجيل نقد تجريبي | لا تحصيل أموال ولا إدخال بيانات بطاقة |
| الإيصال | ملخص قابل للنسخ | موسوم محاكاة، وليس فاتورة ضريبية |
| التقييم | نجوم 1–5 وتعليق اختياري بعد الإكمال ومراجعة الدفع | تقييم واحد؛ يظهر في لوحة الفني وترتيب الخدمة |
| التنبيهات | سجل وتحديد كمقروء وفتح الطلب | تذكير خلال 30 دقيقة للموعد المقبول أثناء فتح التطبيق |
| الملف | تعديل الاسم، دليل التجربة، تبديل الدور والخروج | حفظ البيانات السابقة دون تعديل حساب حقيقي |

## الفني

| المرحلة | السلوك المطور | القيود |
|---|---|---|
| التسجيل | الاسم والتخصص وإقرار ذاتي وتعبئة افتراضية | الإقرار ليس اعتمادًا مهنيًا من المنصة |
| الباقات | 100/200/300 ريال شهريًا، عرض الكل دون اختيار | المستخدم يحدد الباقة صراحة؛ الاشتراك محاكاة |
| الاشتراك | تاريخ الانتهاء، تجديد وتغيير الباقة | لا خصم تلقائي؛ يجب حفظ التجديد عند مغادرة المساحة |
| الخدمات | إضافة وتعديل وتفعيل وإيقاف الخدمات | 3/10/25 خدمة نشطة بحسب الباقة؛ الحجز القديم يحتفظ بتفاصيله |
| لوحة العمل | أعداد الحالات وقيمة المنجز والنقد التجريبي | البيانات المحلية ليست إيرادًا ماليًا حقيقيًا |
| الطلبات | نفس طلبات العميل على الجهاز، مع التصفية | الطلب الجديد يقبل أو يرفض؛ الملغى لا يعاد تنفيذه |
| التنفيذ | قبول → تحرك → بدء عمل → اكتمال | لا تجاوز مرحلة ولا إرسال تحديث قديم |
| الموقع | تقدم مسار افتراضي داخل طلب أثناء التحرك | دون صلاحية GPS أو مشاركة موقع في المحاكاة |
| التوفر | مفتاح معاينة محلي | لا يلغي الطلبات المقبولة ولا ينشر حالة عامة |
| التقييمات | عرض تقييم العميل الفعلي داخل التجربة | لا تُستخدم العينة الثابتة القديمة كتقييم مستخدم |
| التقرير | نسخ ملخص المنجز والنقد التجريبي | متاح في الباقة الاحترافية |

## حفظ البيانات والتحقق

`JourneyStore` يكتب بيانات التجربة عبر طابور داخل العملية، ويعيد قراءة أحدث حالة قبل كل تعديل. يرفض انتقال الحالة إذا تغيرت منذ عرضها. النماذج غير قابلة للتعديل الخارجي، وتحتفظ الحجوزات بنسخ السعر والعنوان والموعد وسجل الحالات. المفضلة والتنبيهات والتقييمات والدور تحفظ في `sulh_connected_journey_v1`، وملف الفني والباقات في `sulh_provider_demo_v1`.

تغطي الاختبارات رحلة كاملة بين الدورين، وفرز البحث العربي، والاستئناف دون رمز دخول، وموعدًا متكررًا وحالة قديمة، والتقييم المكرر والدفع المبكر، وحد الخدمات، وتذكيرًا لا يتكرر، والشاشات العربية الضيقة. تُنفذ اختبارات Flutter وبناء APK في GitHub Actions؛ تشغيل Dart داخل هذه البيئة المحلية غير متاح. نتيجة الإصدار النهائية تسجل في ملف التحقق بعد اكتمال الفحص.

## ما يلزم للإطلاق التجاري

1. فصل اشتراك الفني الحقيقي عن المحاكاة وربطه ببوابة مدفوعات وفواتير وسياسة استرجاع وصلاحيات خادم، بعد تحديد مزود الخدمة والبيانات التجارية.
2. تشغيل تنبيهات الخلفية وقنواتها واختبار وصولها وإعادة جدولتها على أجهزة فعلية. التذكير الحالي داخل التطبيق فقط.
3. اختبار GPS الحقيقي على أجهزة فعلية، وسياسة التوفر واستهلاك البطارية والإذن والخلفية. المحاكاة الحالية لا تتتبع مستخدمًا.
4. تهيئة بريد التحقق والاستعادة وإثبات وصوله، وإدارة اعتماد الفني ومستنداته. الحساب الافتراضي لا يثبت هوية أو كفاءة.
5. مزامنة واجهتي التجربة عبر الخادم إذا أريد الاختبار على هاتفين؛ البيانات الحالية مشتركة محليًا فقط.
6. توقيع Android إنتاجي ثابت، إعدادات متجر وسياسة خصوصية وشروط استخدام واختبارات أجهزة وإتاحة، ومراقبة الأعطال وخطة نسخ احتياطي.

هذه المتطلبات ليست مفعلة لمجرد ظهور شاشة محاكاة لها، ولا يُدّعى أن النسخة التجارية مكتملة التشغيل.
