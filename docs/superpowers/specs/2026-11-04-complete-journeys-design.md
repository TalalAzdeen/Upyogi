# تطوير رحلتي العميل والفني — صلح 1.9

طلب المستخدم تحليل الرحلتين وتطوير جميع مراحل الاستخدام. طلب سابقًا التنفيذ دون أسئلة، وتجاوز تحقق البريد بالمحاكاة، واختيار الباقة بنفسه. الاختيار التنفيذي: تطوير نسخة تجريبية مترابطة داخل تطبيق Flutter الحالي، مع بقاء الحسابات والخادم الحقيقيين متاحين. ليست هذه موافقة على تحصيل أموال أو تشغيل تتبع خفي.

## نتائج مراجعة 1.8

| المرحلة | الوضع الحالي | التغيير |
|---|---|---|
| الدخول | الفني له محاكاة؛ العميل يحتاج كلمة مرور | ترحيب وتسجيل محلي للعميل، ودخول حقيقي مستقل |
| البحث | بحث خادم جيد، لكنه يحتاج اتصالًا وحسابًا للتجربة | كتالوج محلي 24 خدمة، بحث عربي/إنجليزي، مدينة، تصنيف، ترتيب ومفضلة |
| الحجز | طلبات العميل الحقيقية منفصلة عن عينات الفني | سجل تجريبي مشترك للطلب وتفاصيله وتسلسله |
| المواعيد | إلغاء موجود؛ لا إعادة جدولة في المحاكاة | موعد مستقبلي، تحقق البيانات، إلغاء/إعادة جدولة قبل القبول |
| الفني | الباقات 100/200/300 موجودة دون اختيار؛ لوحة عينات منفصلة | مساحة عمل متصلة بطلبات العميل، وإدارة الخدمات ضمن حد الباقة |
| التنفيذ | حالات مختلفة في مساري المحاكاة | Requested → Accepted → OnTheWay → InProgress → Completed، أو Rejected/Cancelled |
| الموقع | الحقيقي مرتبط بشاشة التتبع؛ العينة شكلية | تقدم موقع افتراضي مرتبط بالطلب، موضح أنه محاكاة |
| الدفع | يمكن تخطي الدفع في مسار العميل بالخادم | ملخص وإيصال محلي، تخطي أو تأكيد نقد تجريبي، لا تسجيل Paid حقيقي |
| التقييم | تقييم خادم موجود وعينة فني ثابتة | تقييم واحد 1–5 بعد الإكمال، يظهر للفني والخدمة |
| التنبيهات | سجل منفصل وعرض يدوي | سجل للجانبين، غير مقروء، تذكير داخل التطبيق قبل الموعد بـ30 دقيقة دون تكرار |
| الاستئناف | حفظ فني فقط | استئناف الدور والمرحلة والطلبات محليًا، والحساب الحقيقي يأخذ الأولوية |

## العقود

- لا اعتماد جديد، ولا رموز دخول وهمية، ولا تغيير كلمات مرور أو تعطيل تحقق الحساب الحقيقي.
- كل بيانات هذه الرحلة محلية في SharedPreferences؛ تبادل الأدوار على الجهاز نفسه، وليس مزامنة بين جهازين.
- تبقى الباقات الثلاث ظاهرة دون تحديد تلقائي، وتجديدها تجريبي. حدود الخدمات 3/10/25 في المساحة التجريبية.
- التواريخ والمبالغ ثابتة في الحجز عند الإنشاء. انتقال حالة قديم أو متكرر مرفوض. لا تقييم أو دفع قبل الإكمال.
- لا إعادة حجز نفس الموعد لنفس الفني، ولا إلغاء بعد بدء التنفيذ، ولا تغيير خدمة بعد إنشاء الحجز يؤثر في سعر الحجز القديم.
- البحث يشمل إزالة التشكيل والتطويل وتوحيد الألف والياء. الخدمات المعطلة لا تظهر للعميل، وحجوزاتها السابقة تبقى قابلة للعرض.
- التذكير داخل التطبيق أثناء فتحه، لا ادعاء بتنبيه خلفية أو GPS فعلي أو خدمة دعم متاحة.
- Android الإصدار 1.9.0+13. الاختبار الكامل والبناء عبر GitHub Actions لأن Dart المحلي محجوب في البيئة.

## القبول

عميل جديد يبدأ دون كلمة مرور، يبحث ويحفظ مفضلة ويحجز؛ ينتقل لدور الفني ويسجل ويختار أي باقة، يقبل الطلب ويبدأ التحرك والعمل وينهيه؛ يعود العميل، يرى التسلسل، يتخطى الدفع أو يسجل نقدًا تجريبيًا ويقيّم؛ يعاود فتح التطبيق وتبقى النتيجة. يغطي الاختبار أيضًا رفض الطلب وإلغاءه وإعادة جدولته وحد الباقة والمدخلات الخاطئة والتكرار واللغة العربية والشاشة الضيقة.

## حدود التشغيل الحقيقي المتبقية

اشتراكات مالية حقيقية، مزامنة المحاكاة عبر الأجهزة، تنبيهات الخلفية، تتبع GPS الدائم، استعادة كلمة مرور البريد التجريبي، والتوقيع الإنتاجي الدائم تحتاج عمل تشغيل منفصل. لا تُعرض هذه كميزات مفعلة في هذا الإصدار.
