# Upyogi — الإصدار 1.1.0

تطبيق Flutter لعرض الخدمات وحجزها وإدارة طلبات مقدمي الخدمة. هذا تحديث لنسخة sandeepswain54/Upyogi مع الاحتفاظ بواجهاتها الأساسية.

## ما تغير

- تحديث بيئة البناء إلى Flutter 3.47.7، وGradle 8.14.3، وAndroid Gradle Plugin 8.11.1، وKotlin 2.2.20، وJava 17.
- إصدار التطبيق 1.1.0 ورقم البناء 5. تحدد نسخة Flutter قيم compileSdk وtargetSdk وNDK المتوافقة معها.
- توحيد عناوين المصادقة والخدمات والحجوزات والإشعارات والدفع والتتبع في إعداد واحد.
- إصلاح غياب عنوان تسجيل الدخول. العنوان الافتراضي هو خادم المشروع الأصلي المنشور: `https://servicebookingapi.onrender.com`، ومسار المصادقة `/api/Auth` كما في Swagger الخاص به.
- إضافة مهلة اتصال، ورسائل مفهومة عند ردود تسجيل الدخول غير الصالحة، والتحقق من بيانات الجلسة قبل حفظها.
- استخدام دور الحساب الذي يعيده الخادم، بدلاً من الاعتماد على الاختيار السابق في شاشة الدخول.
- معالجة مغادرة الشاشة أثناء الطلبات، وإضافة إعادة محاولة عند تعذر تحميل ملف مقدم الخدمة أو الاتصال بالتتبع.
- إبقاء الحجز معلقاً عند إلغاء الدفع، وعدم عرض النجاح إلا عند تأكيد الخادم. منع تكرار الدفع بعد إرساله وانتظار تأكيده.
- منع إنشاء حجز مدفوع إذا لم يُضبط Stripe، مع رسالة واضحة بدلاً من استثناء أو حجز يتيم.
- إعادة التحقق من شهادات HTTPS بدلاً من قبول جميع الشهادات.
- استبدال اختبار العداد القديم باختبارات بدء التطبيق والمصادقة والردود غير الصالحة وانتهاء مهلة الاتصال.

## تنزيل APK

افتح Actions ثم Build Android APK. بعد ظهور Success نزّل `Upyogi-1.1.0-APK` من Artifacts، وفك ZIP ثم ثبّت `Upyogi-1.1.0-debug.apk`.

هذه نسخة اختبار موقعة بمفتاح Debug، وليست إصدار متجر. تغيير مفتاح Debug بين أجهزة البناء قد يمنع التحديث فوق نسخة قديمة؛ حذف التطبيق يحذف بياناته المحلية. للنشر والتحديثات المستمرة استخدم مفتاح توقيع إنتاج ثابتاً خاصاً بك.

## إعداد خادمك

من Settings → Secrets and variables → Actions → Variables أضف:

| المتغير | القيمة |
| --- | --- |
| `API_BASE_URL` | أصل خادم HTTPS المتوافق مع الواجهة، مثل `https://your-domain.example`، دون `/api/Auth` |
| `STRIPE_PUBLISHABLE_KEY` | مفتاح Stripe العام `pk_test_...` للاختبار أو مفتاحك العام للإنتاج |

الإعداد القديم `AUTH_BASE_URL` ما زال مدعوماً عندما ينتهي بـ `/api/Auth`؛ يُستخرج منه أصل الخادم. استخدم `API_BASE_URL` في الإعدادات الجديدة.

بدون إعدادات مخصصة يستخدم التطبيق خادم صاحب المشروع الأصلي. هذا الخادم ليس ملكاً لحسابك، وقد يتوقف أو يغير بياناته أو سياساته. لبياناتك وحجوزاتك الحقيقية تحتاج خادماً تملكه وتديره. لا يضم هذا المستودع كود خادم ASP.NET أو قاعدة بياناته.

واجهة الخادم الموثقة متاحة على `/swagger/v1/swagger.json`. تحقق من توافق واجهات Auth وService وBooking وProvider وPayment وReview وNotification وSignalR `/hubs/location` عند استبدال الخادم.

لا تضع مفتاح Stripe السري أو كلمات مرور قواعد البيانات في تطبيق Flutter أو متغيراته العامة. المفتاح السري والتحقق من الدفع وWebhooks يجب أن تبقى في الخادم. يجب أن ينفذ الخادم تأكيد الدفع بصورة موثوقة ويمنع تكرار التحصيل.

## تشغيل محلي

أنشئ ملف `.env` في جذر المشروع (غير مضاف إلى Git):

```env
API_BASE_URL=https://your-server.example
STRIPE_PUBLISHABLE_KEY=pk_test_your_public_key
```

```bash
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test
flutter run
```

ملف البيئة اختياري؛ غيابه لا يمنع بدء التطبيق. وجود إعداد غير صالح لا يعني نجاح الاتصال؛ صحح الرابط إلى خادم HTTPS فعلي.

## توقيع الإنتاج

لا تستخدم مفاتيح صاحب المشروع أو مسار Windows القديم. جهّز مفتاحك الخاص وملف `android/keystore.properties` محلياً، ثم مرر `-PenableReleaseSigning=true` إلى Gradle عند إنشاء إصدار الإنتاج. يحتوي الملف على `keyAlias` و`keyPassword` و`storeFile` و`storePassword`. لا ترفعه إلى GitHub. البناء التجريبي لا يقرأ هذا الملف.

تهيئة Firebase الأصلية ما زالت موجودة في Android. عند تحويل المشروع إلى منتج خاص بك، استبدل `google-services.json` واسم الحزمة بإعدادات مشروعك، وراجع قواعد الوصول وأذونات الموقع. لا يفترض هذا التحديث ملكية خدمات صاحب المشروع.
