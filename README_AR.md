# Upyogi 1.4.0 — طلبات الفني وتتبع التحرك

- العربية والإنجليزية مع حفظ اللغة ودعم اتجاه الواجهة.
- الحجز يُرسل مباشرة، دون بطاقة أو دفع أو شحن داخل التطبيق. يدفع العميل للفني مباشرة بعد انتهاء العمل.
- يفتح حساب الفني على طلبات الخدمة، مع تصفية الطلبات الجديدة وتحديث تلقائي كل خمس ثوانٍ أثناء فتح الصفحة. يقبل الفني الطلب أو يرفضه ثم يبدأ التحرك.
- «بدء التحرك ومشاركة الموقع» يطلب موافقة الفني وإذن الموقع، يرسل أول موقع ويغيّر الحالة إلى «الفني في الطريق». العميل يتابع على خريطة OpenStreetMap؛ يظهر تنبيه عند قدم الموقع أو انقطاع الاتصال.
- على Android يبدأ إشعار خدمة موقع أثناء الرحلة ليستمر التتبع عند فتح الملاحة. لا يُضمن التتبع بعد إغلاق التطبيق أو إجباره على التوقف. تتوقف المشاركة عند مغادرة شاشة الفني أو إتمام الخدمة.
- إكمال الخدمة لا يسجل الدفع كمدفوع، لأن التسوية خارج التطبيق. التتبع محصور بطرفي الحجز ويتوقف الوصول إليه بعد الإكمال.
- تسجيل الخروج ظاهر مباشرة في صفحة طلبات الفني وفي الملف الشخصي، مع تأكيد ومسح بيانات الجلسة المحلية وحفظ اللغة.

قاعدة البيانات: طبّق `backend/supabase/offline_workflow.sql` بعد مخططات الأساس والموقع؛ ثم انشر `upyogi-api`. جداول الدفع السابقة محفوظة للتاريخ، لكن إنشاء عمليات دفع جديدة محظور من الخادم.

هذه نسخة Android تجريبية. يحتاج اختبار الحركة والملاحة على جهازين فعليين ومنح أذونات الموقع. تحديث الطلبات أثناء فتح التطبيق؛ لم تُضف إشعارات دفع للهاتف المغلق.

# Upyogi — الإصدار 1.3.0 (اختبار)

تحديث تطبيق Android المأخوذ من sandeepswain54/Upyogi، مع خادم Supabase مستقل في حسابك. امتداد تثبيت Android الصحيح **APK**.

## العربية والإنجليزية

العربية هي اللغة الافتراضية. لتبديل اللغة اضغط رمز 🌐 في شاشة اختيار الحساب أو تسجيل الدخول أو الملف الشخصي، ثم اختر «العربية» أو «English». يُحفظ الاختيار بعد إغلاق التطبيق وتسجيل الخروج، وتبقى بيانات النموذج عند تبديل اللغة.

تتبع القوائم والحقول وأزرار النظام والتقويم والوقت اللغة المختارة، ويتحول اتجاه الواجهة تلقائيًا بين RTL وLTR. تُترجم عبارات الواجهة وحالات الحجز ورسائل التطبيق، وتُعرض أسماء المستخدمين وأوصاف الخدمات التي يكتبونها كما هي.

## الجديد

- قاعدة بيانات خاصة، ومصادقة Supabase، وتجديد الجلسة، وتسجيل الخروج وتغيير كلمة المرور.
- خدمات وحجوزات وملفات مقدمي الخدمة وتقييمات وإشعارات في قاعدة حسابك.
- شاشة «محفظتي» تعرض الرصيد بالريال السعودي وسجل الشحن وحالته الحقيقية من الخادم.
- منع تعديل الرصيد من التطبيق؛ إضافة الرصيد من Webhook دفع موثّق فقط، مع منع تكرار القيد.
- نقل تتبع الموقع إلى الخادم الخاص، مع تحديث كل 5 ثوانٍ أثناء الحجز المقبول، وفحص صلاحيات الأطراف.
- الاحتفاظ بتحديثات Flutter 3.47.7، Gradle 8.14.3، AGP 8.11.1، Kotlin 2.2.20، وJava 17 وإصلاحات الاتصال والمصادقة والدفع السابقة.

## التشغيل

بعد تثبيت APK، اختر عميلًا أو مقدم خدمة، وسجّل بريدًا وكلمة مرور. يلزم تأكيد البريد قبل الدخول. حسابات الخادم القديم منفصلة ولا تُنقل كلمات مرورها إلى قاعدة البيانات الجديدة.

الخادم الافتراضي:
`https://prsyiadiplvumfjesfdf.supabase.co/functions/v1/upyogi-api`

«الملف الشخصي ← محفظتي» يعرض الرصيد. الشحن يتطلب إكمال إعداد Stripe في الخادم؛ إلى ذلك الحين يظهر معطّلًا برسالة واضحة. عند تفعيله لا يظهر نجاح الشحن إلا بعد تأكيد الخادم. ظهور نافذة الدفع وحده لا يثبت إضافة الرصيد.

## ما يحتاج إعدادًا خارجيًا

- مفاتيح Stripe وWebhook لم تُضبط، ولم يُنفَّذ شحن مالي حقيقي.
- إعداد SMTP وقالب رابط التأكيد وعنوان إعادة التوجيه، وتجربة رسالة على بريد حقيقي، مطلوبة قبل الاستخدام العام.
- رصيد المحفظة في هذه النسخة مخصص للشحن والعرض؛ السحب والاسترداد والدفع من الرصيد غير مضافة.
- لا يوجد فريق دعم أو تسوية نزاعات مفعّل في هذه النسخة.

راجع [دليل الخادم والدفع](backend/README_AR.md) للتفاصيل. لا تضع مفاتيح سرية في التطبيق أو المستودع.

## البناء والتنزيل

GitHub Actions → Build Android APK. يتولى المسار تحليل Flutter والاختبارات ثم بناء `Upyogi-1.3.0-debug.apk` في artifact باسم `Upyogi-1.3.0-APK`.

محليًا:

```sh
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test
flutter build apk --debug
```

ملف `.env` اختياري؛ مسار Actions ينشئه تلقائيًا. `API_BASE_URL` يستبدل عنوان API، و`STRIPE_PUBLISHABLE_KEY` مفتاح عام اختياري. يقرأ التطبيق المفتاح العام أيضًا من إعدادات خادم الدفع عند تفعيله.

هذه نسخة Debug للاختبار. قد تختلف مفاتيح توقيع Debug بين أجهزة البناء؛ حذف النسخة القديمة يحذف بياناتها المحلية. لإصدار متجر وتحديثات ثابتة استخدم مفتاح إنتاج ثابتًا عبر `android/key.properties` خارج Git وفعّل `-PenableReleaseSigning=true`. لا تُنشر كلمات مرور أو ملف keystore في المستودع.
## التشغيل والتحقق

```sh
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test --reporter expanded
flutter build apk --debug
```

البيئة المثبتة في GitHub Actions: Flutter 3.47.7 وJava 17. عنوان API الافتراضي في `lib/services/app_config.dart`. يمكن ضبط `API_BASE_URL` في `.env` أو متغيرات Actions. لا تُضع مفاتيح الخادم داخل التطبيق.
