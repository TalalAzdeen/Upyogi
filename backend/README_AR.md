# خادم Upyogi الخاص — Supabase

مشروع Supabase: `prsyiadiplvumfjesfdf`، المنطقة `ap-south-1`.
عنوان API: `https://prsyiadiplvumfjesfdf.supabase.co/functions/v1/upyogi-api`.

نُشرت جداول الحسابات ومقدمي الخدمة والخدمات والحجوزات والتقييمات والإشعارات والمواقع والمحفظة، ودالة `upyogi-api`. لا يستخدم هذا الخادم حسابات صاحب المستودع الأصلي.

## الحسابات

تسجيل البريد وكلمة المرور عبر Supabase Auth، مع تأكيد البريد مفعّلًا. لا تُعطّل تأكيد البريد لتجاوز إعداد الرسائل. تطبيق Android يعرض رسالة تطلب التأكيد قبل الدخول. يجب ضبط SMTP وقالب التأكيد وعنوان إعادة التوجيه في إعدادات Auth قبل الاستخدام العام؛ اختبار تسليم رسالة إلى بريد حقيقي لم يكتمل بعد. حسابات الاختبارات مؤكدة اصطناعيًا ومخصصة للاختبار.

الخادم يتحقق من JWT عبر `getUser` قبل قراءة البيانات الخاصة، ويستخرج الدور من جدول الحسابات. بيانات التسجيل تسمح فقط بدور Customer أو Provider؛ لا يوجد دور إداري يختاره المستخدم. API يتولى صلاحيات الملكية؛ جداول الخدمات والحجوزات الخاصة لا تقبل الوصول المباشر من العملاء. سياسات RLS تمنع تعديل الرصيد أو دور الحساب من التطبيق.

## إعداد الدفع المطلوب

في أسرار Edge Functions أضف، عبر إعدادات Supabase الآمنة:

- `STRIPE_SECRET_KEY`: ابدأ بمفتاح اختبار `sk_test_...`.
- `STRIPE_PUBLISHABLE_KEY`: المفتاح العام المطابق `pk_test_...`.
- `STRIPE_WEBHOOK_SECRET`: سر توقيع endpoint الخاص بالمشروع.

عنوان Webhook:
`https://prsyiadiplvumfjesfdf.supabase.co/functions/v1/upyogi-api/stripe-webhook`
الحدث المطلوب: `payment_intent.succeeded`.

لا تضف الأسرار إلى Flutter أو GitHub أو هذه الوثيقة. الخدمة تستخدم مفاتيح Supabase الخادمية التي توفرها بيئة Edge Functions تلقائيًا. لم تُضبط مفاتيح Stripe أثناء هذا التحديث، لذا الشحن غير مفعّل ولا تُقبل أموال حتى إعدادها والتحقق منها.

كل شحنة بالريال السعودي: من 10 إلى 10,000 ريال. المبلغ محفوظ بالهللات كعدد صحيح. ينشئ الخادم PaymentIntent ويربطه بصاحب المحفظة؛ طلب إعادة المحاولة يستخدم مفتاح idempotency. لا يتغير الرصيد عند نجاح شاشة الدفع وحدها. يتحقق Webhook من توقيع HMAC والزمن والمبلغ والعملة، ثم يضيف الرصيد وسجل العملية في معاملة واحدة تمنع احتساب الحدث مرتين.

لا تشمل هذه النسخة السحب أو الاسترداد أو الدفع من رصيد المحفظة مقابل الحجز. الحجوزات تستخدم دفع Stripe منفصلًا. لا تبدأ استقبال مدفوعات حقيقية قبل اختبار الشحن، تكرار الإشعارات، انقطاع الاتصال، الإلغاء، والاسترداد مع حساب بوابة يدعم نشاطك وبلدك.

## النشر والتحقق

المصدر: `supabase/functions/upyogi-api/index.ts`؛ الاعتماد مثبت على `@supabase/supabase-js@2.95.0`.

ملفات SQL تمثل المخطط المنشور، وتُطبق مرة واحدة على قاعدة جديدة؛ لا تُعد تشغيلها على قاعدة تحتوي الجداول نفسها. دالة API تشمل تسجيل الدخول والتجديد، الملف الشخصي، الخدمات، الحجوزات، الإشعارات، التقييمات، المحفظة، وتتبع الموقع للحجز المقبول عبر طلبات مصادقة كل 5 ثوانٍ.

التتبع يقتصر على العميل ومقدم الخدمة المرتبطين بالحجز؛ إرسال الموقع لمقدم الخدمة فقط. وثائق KYC في حاوية خاصة. التتبع يحفظ آخر موقع، وليس سجل تحركات.

`tests/live_api_test.py` يختبر خادمًا حيًا بحسابات اختبار مؤكدة. يأخذ كلمة المرور من `UPYOGI_TEST_PASSWORD` ولا يخزنها. لا ينفذ دفعة مالية. اختبارات دفتر المحفظة يجب تشغيلها داخل معاملة تنتهي بـ ROLLBACK.

فحص Supabase الأمني لم يظهر تحذيرات أو أخطاء؛ معلومات RLS بلا سياسات للجداول الخاصة مقصودة لأنها متاحة للخادم فقط. الفهارس الجديدة قد تظهر كغير مستخدمة قبل تراكم الاستعلامات.

## البحث الجغرافي ورسائل التأكيد (1.6)

بعد المخطط الأساسي طبّق `nearby_and_email.sql` ثم `email_delivery_receipts.sql` مرة واحدة. انشر `functions/upyogi-api/index.ts` مع `domain.mjs`. تبقى مصادقة المسارات الخاصة داخل الوظيفة باستخدام Auth وملكية السجل، بينما التسجيل والبحث وwebhook الموقّع متاحة دون JWT البوابة.

اختبارات المنطق: `node --test backend/supabase/functions/upyogi-api/domain.test.mjs`. اختبارات قاعدة البيانات: `backend/tests/nearby_email_assertions.sql`؛ تُنشئ سجلات داخل معاملة تتراجع بالكامل ولا ترسل رسائل. صلاحيات RPC وصندوق البريد محصورة بـservice_role مع تفعيل RLS. لا تمنح anon أو authenticated صلاحية قراءة صندوق البريد.

أسرار الإنتاج المطلوبة للبريد: `RESEND_API_KEY`, `EMAIL_FROM`, `RESEND_WEBHOOK_SECRET`. إعداد Custom SMTP في Auth مستقل عن بريد تأكيد الحجز. تفاصيل الإعداد في README_AR الرئيسي. لا يوجد ادعاء بإرسال أو توصيل قبل استجابة المزود وإشعار التسليم الموقّع، ولا تُرسل رسائل للحجوزات القديمة تلقائيًا.
